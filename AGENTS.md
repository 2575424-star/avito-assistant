# Правила работы в Avito Assistant

Над проектом работают владелец Павел и несколько ассистентов: ChatGPT/Codex и Claude Code. Эти правила обязательны для всех.

Перед началом работы прочитай: этот файл → `docs/ONBOARDING.md` (что за система и где что лежит) → `docs/WORKLOG.md` (что уже сделано, решения, открытые вопросы, кто что делает сейчас).

## Журнал — главный способ понимать друг друга

- `docs/WORKLOG.md` ведём все. После каждой завершённой работы (PR, пакет материалов, эксперимент, решение владельца) добавь запись **вверх** раздела «Журнал»: дата, кто, что сделано, где лежит (PR, файлы), что проверено, что осталось.
- Решения владельца — в раздел «Решения» (с датой). Не пересказывай их по памяти, ссылайся на запись.
- Взял задачу — впиши себя в «Сейчас в работе». Закончил — убери оттуда и добавь запись в журнал.
- Меняешь то, что сделал другой ассистент (код, правила, стратегию, выводы), — можно, но не молча: в журнале напиши, что и почему поменял. Если сомневаешься, правильно ли, — сначала вопрос в «Открытые вопросы».
- Журнал без персональных данных: без имён клиентов, телефонов, текстов реальных переписок.

## Ветки и Pull Request

- `main` — рабочая версия. Railway **автоматически выкладывает каждое слияние в `main`** (сервис `avito-assistant`, адрес https://avito-ai-platon.up.railway.app).
- Работа — в отдельной ветке от свежей `main`. Префиксы: `claude/…` — Claude Code, `gpt/…` — ChatGPT/Codex.
- Не пушь напрямую в `main`, не переписывай историю чужих веток (без rebase/force-push).
- PR: что изменено, зачем, какие проверки прошли. Ассистент может слить свой PR сам, если `npm test` зелёный и нет открытых замечаний.
- После слияния проверь, что деплой на Railway в статусе SUCCESS и сервис стартовал без ошибок; если нет — откати на предыдущий успешный деплой и сообщи Павлу.

## Кто что может менять

**Оба ассистента — ChatGPT/Codex и Claude Code — могут менять в проекте всё**: код сервиса (`src/`, `public/`, `test/`), общий слой правил агента, стратегии, сценарии, документацию. Условия одни для всех:

- работа в своей ветке и через PR, `npm test` зелёный (если менялся код);
- запись в журнале: что изменил, зачем, что проверил;
- если PR затрагивает недавнюю работу другого ассистента — упомяни это в PR и в журнале, чтобы он увидел.

Авторы стратегий (для сравнения в «Лаборатории»): `codex_business`, `codex_friendly` (+ `friendly_examples.md`) — Codex; `claude_independent` — Claude Code. Общий слой `src/lab/common_rules.md` начинал Codex. Править может любой из двух.

Версии промптов неизменны: результаты прогонов привязаны к версии. Правка стратегии или общего слоя = новый номер (`v0.3.1`), старую версию не переписывать, в журнале — что и почему поменялось. Изменил сценарий «Лаборатории» (`src/lab/*_questions.jsonl`) — повысь его `version`.

Codex может работать напрямую в репозитории (ветки `gpt/…`) или передавать материалы пакетом — тогда Claude Code переносит их в репозиторий и отмечает в журнале «перенесено из пакета Codex vX».

## Нельзя без подтверждения Павла

- Включать **боевой режим** (`send_enabled`, отправка клиентам в Авито) и любые рассылки. По умолчанию всё — тестовый режим: черновики, в Авито ничего не уходит.
- Удалять данные, чаты, базу знаний, прогоны, тома и сервисы; необратимые миграции базы.
- Вводить или менять секреты (ключи OpenAI, Авито, Telegram, пароль): их вписывает Павел в интерфейсе или переменных Railway.
- Подавать жалобы (опротестования) в Авито — только человек.

## Данные и безопасность

- В репозиторий **нельзя**: ключи, токены, пароли, `.env`, реальные переписки, телефоны, имена клиентов и сотрудников, выгрузки чатов (JSONL), результаты прогонов с персональными данными. Репозиторий **публичный**.
- Реальные выгрузки и пакеты — только локально в рабочей папке сессии.
- Тестовые сценарии — обезличенные, с учебными фактами.
- Изменения структуры базы — только добавление (новые таблицы/колонки через миграцию в `src/db.js`), удаление старого — отдельным PR после проверки.

## Проверки перед PR

- `npm test` — сквозной тест на моках Авито и OpenAI (запускается без ключей).
- PR только с документацией (Markdown) — тесты можно не запускать, отметь это в PR.
- Меняешь интерфейс — посмотри страницу в браузере (Chromium есть в среде Claude Code).

## Как работать с Павлом

Павел не программист: по-русски, простыми словами, конкретные шаги и прямые ссылки. Не просить присылать ключи в чат. Перед рискованным действием — спросить. Платные прогоны моделей — с оценкой стоимости и лимитом.
