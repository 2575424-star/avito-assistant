# Аналоги и готовые решения для чатов Авито

Обзор от 24.09.2026. Цель: найти открытые проекты и готовые сервисы, которые работают с чатами Авито, сравнить их с нашим ассистентом и решить, что взять себе.

Исходники открытых проектов скачиваются командой `scripts/fetch-references.sh` в папку `references/`. Папка в `.gitignore`: чужой код в репозиторий не коммитим, он нужен только для сравнения.

## Итог в двух словах

- **Готового открытого AI-менеджера для Авито под автодилера нет.** Всё открытое на GitHub — это либо SDK и MCP-серверы (обёртки над API без логики продаж), либо узкие боты под другую нишу.
- **Самый близкий по смыслу проект — `marko1olo/avito-dental-ai-bot`** (AI-бот для стоматологии на Авито). У него стоит взять несколько идей: вето-слой, «человеческую» задержку и дожим молчащих клиентов.
- **Наш подход к API совпадает с лучшими проектами:** те же эндпоинты, та же форма вебхука. Нашлись две полезные поправки к нашему плану (см. «Что проверить у себя»).
- Коммерческие аналоги (ИИ Диалоги, avChat, Intly и др.) — закрытые SaaS, код взять нельзя, только функции для сравнения.

### avito-dental-ai-bot — подробно

Архитектура: Playwright-скрапер читает непрочитанные чаты из веб-версии Авито и кладёт в SQLite; Python-ядро решает, что делать с сообщением; ответ либо уходит сам, либо приходит черновиком в Telegram-группу с кнопками «Отправить / Изменить / Игнорировать / Забрать / Пауза».

Что у них сделано хорошо и чего нет у нас:

1. **Вето-слой после LLM (`brain/guard.py`).** Регулярки проверяют готовый ответ до отправки: каждая сумма в рублях сверяется со списком разрешённых цен, запрещены обещания («гарантируем», «100 %»), посторонние ссылки и контакты, больше двух вопросов подряд, слишком длинный текст. Сработало — ответ не уходит клиенту, а идёт человеку с причиной. Принцип: модель пишет, но цифру выдумать не может.
2. **Белый список вместо чёрного (`brain/gate/intent.py`).** Автоматически уходит только то, что уверенно распознано как безопасное (адрес, график, парковка, приветствие). Цены, кредит, запись и всё непонятное — черновик администратору. Гейт детерминированный, без вызова LLM, покрыт тестами.
3. **«Человеческая» задержка (`brain/delay.py`).** Первый ответ через 40–90 с, дальше 15–45 с, плюс время набора (~250 знаков в минуту) и случайный разброс. Вне рабочих часов ответ откладывается. У нас фиксированная задержка 15 с.
4. **Дожим молчащего клиента (`brain/followup.py`).** Не больше двух сообщений: через 3–5 ч и через 24 ч после нашего последнего ответа. Не отправляется, если клиент отказался («не актуально», «нашёл другую»), оставил телефон, обещал позвонить сам или диалог забрал человек. По умолчанию тоже черновиком.
5. **Каскад LLM-провайдеров (`brain/llm/`).** Несколько ключей и моделей, переключение при 429 и 5xx.
6. **Маскировка телефонов в логах (`brain/pii.py`)**, хэши вместо номеров в базе (152-ФЗ).
7. **425 unit-тестов** на гейт, вето, задержки и дожим.

Чего брать не надо: транспорт через браузер. Он ломается при смене вёрстки Авито и нарушает правила площадки. У нас официальный Messenger API.

### avito-mcp — что полезно

- Подтверждает нашу схему вебхука: у Авито **нет заголовка подписи**, единственная защита — секрет в пути URL. Пункт HANDOFF «проверка подписи `x-avito-messenger-signature`» можно закрыть как неактуальный.
- Авито ждёт ответ `200` **за 2 секунды**, иначе повторяет и может отключить подписку. При подписке Авито шлёт проверочный запрос с телом `{}` без `payload`, на него тоже нужен `200`.
- Секрет сравнивается за постоянное время (`crypto.timingSafeEqual` по хэшам) — у нас обычное `!==`.
- Есть методы, которых у нас нет: `getVoiceFiles` (ссылки на голосовые сообщения), отправка картинок, blacklist.

### avito-raw-export — что полезно

- Корректная обработка 429: ждёт по заголовку `Retry-After`/`X-RateLimit-Retry-After`, повторяет и при 5xx. У нас один повтор через фиксированные 2 с.
- Системные сообщения с `author_id=0` отделяются от клиентских — у нас так же.
- Можно выгрузить все старые переписки кабинета в `conversations.jsonl` и прогнать через «Тест агента» или LLM-оценку: сравнить наши ответы с тем, как отвечали менеджеры и «ИИ Диалоги».

### tg-support-bot — что полезно

- Идемпотентность вебхука: по `id` события повторная доставка отбрасывается (кэш на 10 минут).
- Режим «AI пишет черновик — оператор подтверждает» и поддержка нескольких провайдеров (OpenAI, DeepSeek, GigaChat) через общий интерфейс.
- Форма тела вебхука v3 совпадает с тем, что разбирает наш `server.js` (`payload.value.chat_id`).

## Что предлагаю взять к себе (по приоритету)

1. **Вето-слой перед отправкой** (идея из `guard.py`, переписать на JS под автосалон). Проверять ответ модели на: цены и суммы, которых нет в объявлении или фиде; обещания по кредиту, одобрению, скидкам, трейд-ину («гарантируем», «одобрим 100 %», «без первого взноса»); чужие ссылки и телефоны; длину и число вопросов. Нарушение → ответ не уходит, чат передаётся менеджеру с причиной, уведомление в Telegram. Небольшой модуль, заметно снижает риск.
2. **Режим «черновик»** для рискованных тем: бот готовит ответ, менеджер подтверждает кнопкой в Telegram или в нашем интерфейсе. Удобно для первых недель после запуска.
3. **Задержка по длине ответа + рабочие часы** (`delay.py`): первый ответ 40–90 с, дальше короче, плюс время набора и разброс.
4. **Дожим** (`followup.py`) — совпадает с нашим пунктом 8 «Рассылки и напоминания»: максимум 2 сообщения, стоп-слова отказа, не писать после телефона или «сам позвоню».
5. **Надёжность API:** 429 с `Retry-After` и повтор при 5xx (из avito-raw-export), отбрасывание повторных доставок вебхука по `id` события (из tg-support-bot), сравнение секрета за постоянное время (из avito-mcp).
6. **Голосовые сообщения:** `getVoiceFiles` → распознавание (например, OpenAI Whisper) → текст в историю. Покупатели авто часто пишут голосом.
7. **Оценка качества на реальных диалогах:** выгрузить старые переписки через avito-raw-export и прогнать через агента для сравнения.

## Что проверить у себя

- В HANDOFF (раздел 4, «Надёжность») запланирована проверка подписи `x-avito-messenger-signature`. По данным avito-mcp такого заголовка у Авито нет; защита — секрет в URL. Пункт стоит заменить на идемпотентность и сравнение секрета за постоянное время.
- Наш вебхук сначала дочитывает тело, потом отвечает `200`. Проверочный запрос `{}` без `payload` обрабатывается правильно (просто ничего не синхронизируется). При обычной нагрузке укладываемся в 2 с.
