# Лаборатория: 3 стратегии × 2 модели

Реализация задания v0.3.0 (START_HERE из пакета Codex). Раздел «Лаборатория» в интерфейсе.

## Что сравниваем

| Стратегия | Автор | Файл |
|---|---|---|
| codex_business v0.3.0 | Codex | `src/lab/codex_business.md` |
| codex_friendly v0.3.0 | Codex | `src/lab/codex_friendly.md` + библиотека `friendly_examples.md` |
| claude_independent v0.3.0 | Claude Code | `src/lab/claude_independent.md`, гипотеза — [claude_independent.md](claude_independent.md) |

Все три — поверх общего слоя Codex `src/lab/common_rules.md` (v0.2.0, без изменений). Модели: GPT-6 Sol (`gpt-6-sol`) и GPT-6 Luna (`gpt-6-luna`), OpenAI. Прежние A/B/C переведены в архив (история прогонов сохранена).

Каждый запрос: общий слой + одна стратегия + учебные факты сценария (JSON) + строка «СОСТОЯНИЕ ЧАТА» (одинаково для всех) + адаптер формата ответа (JSON `reply/phone/handoff/skip`) + история **только этой комбинации**.

## Вопросы

- 12 стандартных сценариев Codex (`src/lab/standard_questions.jsonl`, часть многоходовые).
- 20 частых вопросов клиентов (`src/lab/faq_questions.jsonl`) — темы и формулировки из реальных чатов кабинета, обезличены, факты учебные.
- Свои вопросы — кнопка «+ Свой вопрос».

## Как запустить (владелец)

1. **Ключи.** В OpenAI (platform.openai.com) создайте два проекта — «Avito Sol» и «Avito Luna», в каждом разрешите свою модель, поставьте лимит расходов и создайте API-ключ. В сервисе: Настройки → **Ключи и модели** → добавьте профили «Sol» и «Luna», привяжите модели к профилям, проверьте цены. Ключи хранятся только на сервере, в интерфейсе и экспорте — маска.
2. **Лаборатория** → отметьте стратегии, модели и вопросы → укажите лимит в долларах → «Запустить». Перед запуском видно число запросов и ожидаемый расход. Прогон останавливается при достижении лимита или по кнопке «остановить» (начатые запросы завершаются и сохраняются).
3. **Ответы по вопросу**: 6 карточек (строки — стратегии, столбцы — модели): ответ, модель, версия, API, время, токены (вход/кэш/выход/reasoning), стоимость, автопроверки. Оценки 1–5 по пяти критериям, отметка критической ошибки, комментарий, «как надо было». Режим **слепой оценки** скрывает стратегию и модель и перемешивает карточки до оценки.
4. **Сводка** по шести комбинациям: прогоны, ошибки, доля оценённых, средние оценки, критические ошибки, медиана времени, токены, стоимость. **Экспорт JSON** — результаты, конфигурации, сценарии (без ключей).

Полный прогон всех 32 вопросов × 6 комбинаций ≈ 210 запросов, по ценам из пакета Codex — примерно $1–3 (почти всё — Sol). Для первого просмотра достаточно 10–20 вопросов.

## Изоляция

Код лаборатории (`src/lab.js`, `src/llm.js`) не использует модули Авито, чатов, лидов и уведомлений; пишет только в таблицы `lab_*` и снимки промптов. Тест `npm test` проверяет: ни одной отправки и отметки «прочитано» в Авито, число чатов, сообщений, лидов и черновиков не меняется, каждая модель ходит со своим ключом, ключи не попадают в ответы API и экспорт.

## Расходы

usage читается из ответа модели: вход (включая кэш), кэш, выход (включая reasoning). Стоимость = (вход − кэш) × цена входа + кэш × цена кэша + выход × цена выхода; если цена кэша не задана — по цене входа (с запасом). Нет usage — стоимость «неизвестна», а не ноль. Это расчёт, не списание: сверять с Usage в каждом проекте OpenAI.

## Проверки

`npm test` — сквозной тест на моках, включая лабораторию: 18 прогонов (3 вопроса × 6 комбинаций), многоходовой сценарий с раздельной историей, расчёт стоимости, лимит, ошибка модели, переход на Chat Completions, отдельные ключи, изоляция.

## Не проверено и открытые вопросы

1. **API и цены GPT-6 не сверены**: документация OpenAI из среды разработки недоступна. Адаптер поддерживает Responses API и Chat Completions, сам убирает неподдерживаемые параметры (temperature, reasoning, JSON-формат) и сохраняет, как фактически прошёл запрос. Цены — из пакета Codex, правятся в настройках.
2. **Общий слой Codex не менялся**, хотя в нём два места расходятся с решениями: «виртуальный помощник» в разделе «Роль» (решение — Ярослав, менеджер отдела продаж) и R15 «правила оплаты не получены» — правила уже получены (`docs/avito-cpa-rules.md`). Предлагаю v0.3.1 общего слоя с этими правками — по решению владельца.
3. Строка «СОСТОЯНИЕ ЧАТА» (реплики и платность по правилам Авито) добавлена всем трём стратегиям одинаково.
4. 26 регрессионных проверок Codex ещё не переведены в исполнимые сценарии: у них нет явных учебных фактов.
5. Автопроверки — подсказки для оценщика, не замена оценки человека.
