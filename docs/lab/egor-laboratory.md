# Лаборатория GPT: Егор, egor-1

Решение владельца от 24.09.2026: отдельный экран `#/gpt-lab`, два стиля Codex × GPT-6 Sol/Luna. Последнее имя роли — Егор, менеджер отдела продаж автосалона InDrive. На прямой вопрос об автоматизации отвечает честно.

## Как пользоваться

1. Выбрать вопросы (16 сценариев с учебными фактами), нажать «Сгенерировать четыре ответа».
2. Сравнить формальный и неформальный варианты на обеих моделях. Многоходовой сценарий показывает весь диалог каждой комбинации.
3. Выбрать лучший ответ, сохранить исправление, комментарий и при необходимости существенную ошибку.
4. Вернуться к прогону через историю. Исправления сохраняются для анализа; они не меняют действующий промпт автоматически. Улучшение выпускается новой версией после проверки.

Контрольные ответы в раскрывающемся блоке — авторские ориентиры, не результаты модели. Модель получает факты, собственную историю, общий слой и свою стратегию; эталоны ей не передаются. Вопросы включают цену, наличный расчёт, комплектацию, трейд-ин, кредит, лизинг, сроки/предоплату, возражения, визит, отказ от телефона, системные события и отказ от сообщений.

Учебные факты не являются действующим предложением салона. Настоящие условия компании необходимо отдельно утвердить перед подключением к клиентским чатам.

## Изоляция и версии

- `src/gpt-lab/common.md`, `formal.md`, `friendly.md`: новая версия `egor-1` с ключами `gpt_egor_formal` и `gpt_egor_friendly`. Статус `lab_only`; рабочий агент и прежние три стратегии не переключаются.
- `src/gpt-lab/cases.json`: 16 новых сценариев и контрольные ответы. Старые сценарии и результаты сохраняются.
- `src/gpt-lab.js`: существующий движок `src/lab.js`, отдельная задача `gpt_lab`; нет вызовов отправки в Авито, записи лидов или изменения базы знаний.
- Выбираются существующие профили OpenAI для точных имён `gpt-6-sol` и `gpt-6-luna`; профили должны различаться. Ключи не меняются и не возвращаются новому экрану.
- В новом интерфейсе нет расходов. Внутренний предохранитель — 16 вопросов, один повтор, параллельность 2, порог учтённого/оценённого расхода $25. Это **мягкий порог**, не банковский лимит: уже начатые запросы могут завершиться после остановки, оценка не гарантирует фактическую стоимость. Для жёсткого ограничения нужен бюджет проекта OpenAI.
- Выбор сохраняется в новой таблице `gpt_lab_choices`, замечания — в существующих полях `lab_runs`. Миграция только добавляет таблицу.

Остальные ограничения: лимит мягкий; regex-проверки не доказывают качество/фактическую точность; сравнение чисел с карточкой может давать ложные предупреждения; семантическую оценку делает человек. Цена кэша в существующих настройках может быть пустой (тогда стоимость оценивается по обычному входу). Настройки владельца не перезаписываются.

**В-3.** Все 26 прежних регрессионных проверок в этой поставке не переносились. Новые 16 исполнимых сценариев покрывают основной пользовательский цикл; перенос оставшегося набора остаётся открытой задачей. Не считать его завершённым по этой записи.

Дублирование базовых ограничений нормально; отличимость нужно проверять слепой оценкой. Требование просить номер не позднее второго ответа и договориться к третьему ходу слишком жёсткое при отказе, жалобе или недостающих фактах. Рекомендация — привязать момент к полезной выполнимой задаче и готовности клиента. Стратегия Claude сохранена без изменений; в новом сравнении её нет по последнему заданию владельца.

| Модель | Вход / 1M | Чтение кэша / 1M | Выход / 1M | Запись кэша / 1M |
|---|---:|---:|---:|---:|
| gpt-6-sol | $2 | $0.20 | $10 | $2.50 |
| gpt-6-luna | $0.10 | $0.01 | $0.50 | $0.125 |

Это Standard для короткого контекста, без региональных/ускоренных надбавок. Существующая формула учитывает вход, чтение кэша, выход; отдельную запись кэша не учитывает, поэтому её нельзя считать точным биллингом всех режимов. В обеих моделях поддерживается Responses API и `reasoning.effort`: none, low, medium (по умолчанию), high, xhigh, max. Приложение передаёт JSON mode через `text.format.type=json_object`, а reasoning через `reasoning.effort`; схема параметров соответствует Responses. JSON mode гарантирует формат JSON, но не схему полей — сейчас это проверяется парсером, строгую JSON Schema можно добавить отдельно. Токены reasoning входят в оплачиваемый выход; повторно прибавлять их к output не следует. Доступность моделей для конкретных ключей и фактическое качество проверяются реальным прогоном, а не документацией.
